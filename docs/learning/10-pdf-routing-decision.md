# 学习 10：PDF 第一版解析路由决策

状态：2026-10-19 基线实验已完成验收，第一版路由决策待最终确认。

## 决策目标

为当前 RAG 项目确定可评测、可追溯的 PDF 解析路线。第一版优先保证失败可见和来源可追溯，
不追求一次支持所有 PDF，也不把解析后的整篇文档直接送入 Embedding。

## 最终路线

~~~text
PDF
  -> PyMuPDF 页面诊断与快速提取
       ├─ 普通原生文字页 -> PyMuPDF 作为正文结果
       ├─ 已知复杂版式页 -> Docling 重新解析版面与阅读顺序
       ├─ 整页扫描图像   -> RapidOCR full_page
       └─ 无法可靠分类   -> failed / 人工检查，不静默进入 RAG
~~~

路由以页面为判断单位，因为一个 PDF 可以同时包含原生文字页、扫描页和混合页。一次文档处理
仍应复用同一个解析器实例，避免重复加载模型。

## 第一阶段：PyMuPDF 诊断

所有 PDF 先经过 PyMuPDF。它负责：

- 固定文件 SHA-256 和页数；
- 获取页面尺寸、文本字符数、图片数量及图片覆盖率；
- 快速提取原生文字、页码和 bbox；
- 对空文本、扫描页和隐藏 OCR 层发出明确状态与警告；
- 使用高置信度重复规则分类页眉和页脚，但不删除原始文字。

当前诊断阈值是：有效文字至少 20 个非空白字符，整页图片覆盖率至少 0.8。这些阈值只在
当前样本和自动 fixture 上验证过，增加新类型 PDF 时必须重新评估。

## 第二阶段：选择解析路径

### 普通原生文字页

默认使用 PyMuPDF。适用于单栏、阅读顺序清楚、没有复杂表格和多栏结构的页面。它速度快、
依赖轻，并能稳定提供页码和 bbox。

### 复杂版式文字页

使用 Docling。触发信号包括：

- 双栏或多栏正文；
- 需要标题、列表、图注、表格等语义类型；
- PyMuPDF 的 block 顺序与视觉阅读顺序不一致；
- 页面包含多个相互穿插的图片、正文或脚注区域。

当前项目已经验证 Docling 路径，但尚未实现全自动“复杂版式分类器”。第一版调用方需要根据
样本类型或人工配置选择 Docling；自动复杂度检测属于后续工程任务。

### 扫描页和隐藏 OCR 页

整页图片覆盖率达到 0.8 时采用 RapidOCR `full_page`：

- 没有文字层：页面状态先标为 `needs_ocr`，OCR 成功后才变成 `parsed`；
- 有隐藏 OCR 层：保留其结果用于质量对照，但第一版不把它作为最终正文；
- 最终 OCR block 标记为 `rerun_ocr`，不得与 `embedded_ocr` 静默混合。

这个保守策略会增加处理时间，但当前扫描样本已经证明隐藏 OCR 会把 `属于` 错成 `属千`、
把 `Scalability` 错成 `Scalab山ty`，而整页重跑修复了这两个已知错误。

## 统一输出与追溯

所有路径必须输出同一个 `ParsedDocument` 契约：

- `ParsedDocument`：文件哈希、来源、解析器和版本；
- `ParsedPage`：一页起始页码、尺寸、类型、状态和警告；
- `ParsedBlock`：文字、语义类型、阅读顺序、bbox 和提取方法；
- `ParsedPicture`：图片区域 bbox 及其子文字 block；
- `ChunkCandidate`：后续 chunk 阶段的结构化输入。

坐标统一使用左上角原点、PDF point 和 `(x0, y0, x1, y1)`。下游不应依赖 PyMuPDF 或
Docling 的私有输出格式。

## 失败策略

以下情况不得返回“成功的空结果”：

- 页面没有有效文字且需要 OCR：`needs_ocr`；
- OCR 或版面解析完成后仍没有有效 block：`failed`；
- bbox 无效或页面编号不连续：拒绝构造统一结构；
- 图片子文字找不到父图片：记录明确警告；
- 密码保护 PDF：第一版直接失败，不尝试绕过；
- 解析器异常：保留文件哈希、页码和异常信息，停止该路径。

不同解析器的结果保存在独立输出中。除非有明确的 block 对齐规则，否则禁止逐字或逐段静默
混合多个解析器的输出。

## 下一阶段 ChunkCandidate 输入

普通正文 chunk 可以接收：

- `title`、`heading`、`paragraph` 和 `list_item`；
- 单独处理的 `table`、`formula` 和 `figure_caption`；
- 原始 block id、页码、bbox、阅读顺序和章节路径。

以下内容默认不进入普通正文 chunk：

- `header` 和 `footer`；
- `picture_text`；
- 状态为 `needs_ocr` 或 `failed` 的页面；
- 带有必须人工处理的严重警告 block。

`picture_text` 不会被删除。它与 `ParsedPicture` 一起保留，未来可以进入独立图片 chunk 或视觉
模型处理流程。当前 `ChunkCandidate` 会明确拒绝它，防止图中节点按错误线性顺序进入
Embedding。

## 第一版暂不支持

- 从架构图或流程图恢复箭头方向和节点关系；
- 可靠理解图片、照片和图表语义；
- 手写内容和低质量、严重倾斜的扫描件；
- 公式语义、跨页表格和复杂表单的完整结构恢复；
- 自动判断隐藏 OCR 的逐字可信度；
- 完整、无误差的标题层级恢复；
- 全自动复杂版式分类和端到端生产路由器。

这些限制必须显式保留，不能由大模型静默猜测或修复。

## 验收结果

- 三类 PDF 样本均已固定哈希和人工核对事实；
- PyMuPDF、Docling 和 RapidOCR 均输出统一可追溯结构；
- 页码、bbox、解析器版本和提取方式均被保留；
- 扫描页不会静默返回空文本；
- 双栏、页眉页脚、语义类型、OCR 字符替换和图表隔离均完成实验与人工验收；
- 失败案例 FAIL-001 至 FAIL-005 均已通过修复、路由或安全隔离得到处理；
- 下一阶段可以开始结构感知 chunk，而不是继续直接处理整篇长文本。
