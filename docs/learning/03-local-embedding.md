# 学习 03：本地 Embedding 基线

## 我们现在处于哪里

最小 RAG 闭环已经完成纯文本标准化与切分，当前开始把文本块转换为向量：

```text
原始文本 -> 标准化 -> 文本块 -> Embedding -> 向量数据库 -> 检索 -> 回答
                                      ^
                                   当前步骤
```

本阶段先验证“同一个模型能把 query 和 chunk 投影到同一个固定维度的向量空间”，暂时不写入向量数据库。

## 为什么增加适配层

应用代码不直接散落对 Sentence Transformers 的调用，而是通过 `Qwen3Embedder`：

- `embed_query()` 负责查询向量；
- `embed_documents()` 负责批量生成文本块向量；
- `EmbeddingConfig` 固定模型、维度、设备、批大小和缓存位置。

这样以后比较云端 Embedding API 时，可以替换实现而不需要重写切分、索引和检索流程。

## query 和 document 为什么分开编码

Qwen3 Embedding 是面向检索训练的非对称模型。query 编码时使用 `query` prompt，告诉模型这段文字代表“需要寻找答案的问题”；document 编码时不添加该 prompt，表示它是“可能包含答案的资料”。两者最终仍得到相同维度的向量，因此可以计算相似度。

如果误把 document 也按 query 编码，程序仍然能够运行，但检索质量可能下降。这正是适配层和测试需要防止的静默错误。

## 当前基线配置

| 配置 | 当前值 | 理由 |
| --- | --- | --- |
| 模型 | `Qwen/Qwen3-Embedding-0.6B` | 支持中英文与代码，适合本地学习 |
| 设备 | `cuda` | 使用 RTX 2080 Ti |
| 精度 | FP16 | 减少显存占用并利用 GPU |
| 向量维度 | 1024 | 先使用模型的完整维度建立质量基线 |
| 最大长度 | 512 tokens | 第一版 chunk 较短，避免无意义地扩大计算量 |
| 批大小 | 4 | 为 11 GB 显存选择保守起点 |
| 向量归一化 | 开启 | 便于使用余弦相似度或点积比较 |

这些参数是第一版可解释基线，不是永远不变的最优答案。建立检索评测集后，会用实验比较维度、长度和批大小。

## 测试为什么不用真实模型

普通单元测试使用 `FakeEncoderModel`，验证 query prompt、批处理、归一化和向量维度等确定行为。这样测试运行快速、离线且稳定，也不会在 CI 中下载数 GB 权重。

真实模型、显卡和模型文件之间的兼容性属于集成测试，由本地实验单独验证。两类测试解决的问题不同，不能互相替代。
