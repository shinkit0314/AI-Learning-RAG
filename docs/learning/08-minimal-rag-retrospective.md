# 学习 08：最小 RAG 闭环复盘

## 阶段结论

第二个里程碑“最小 RAG 闭环”的学习版基线已经完成，并于 2026-10-17 通过真实模型人工验证。

```text
原始文本
  -> 标准化与稳定文档 ID
  -> 带位置和来源的 chunk
  -> 本地 Qwen3 Embedding
  -> 内存向量索引
  -> query Embedding 与 Top-K 检索
  -> 证据编号和受约束 Prompt
  -> OpenAI Responses API 生成
  -> 本地引用校验与来源回溯
```

## 已验证能力

- 相同文本能够产生稳定的文档和 chunk ID；
- chunk 正文与结构化元数据保持分层；
- query 和 document 使用适合检索任务的不同编码方式；
- 所有向量维度保持一致，无效向量会被拒绝；
- 内存索引支持幂等 upsert、余弦相似度和 Top-K；
- 搜索结果包含正文、分数、来源和字符位置；
- 生成模型只能看到检索出的证据，而不是整个知识库；
- 空答案、缺失引用和伪造引用会被本地代码拒绝；
- 自动测试使用假模型，不下载权重、不访问网络、不产生 API 费用；
- 真实集成实验使用本地 Embedding 和 OpenAI 生成完成端到端验证。

## 首次人工实验结果

问题：

```text
RAG 为什么需要把文本转换成向量？
```

检索结果：

| 排名 | 来源 | 余弦相似度 |
| --- | --- | ---: |
| 1 | `manual://b` | 0.6147 |
| 2 | `manual://a` | 0.5938 |

人工原先认为 A 应排在 B 前面，真实模型则认为包含 RAG、检索、资料和生成流程的 B 与问题整体更接近。A、B 都进入 Top-2，因此召回阶段保留了两类有用证据。这说明单次排序与人工直觉不一致不等于索引错误，也说明后续需要固定评测集，而不能针对一个例子调参。

生成答案同时引用 `[1][2]`，并在证据不足时拒绝补充“向量如何支持语义相似度检索”的外部知识。这是当前证据约束按预期工作的表现，也提示文档内容需要更加完整。

## 目前仍是学习基线

当前实现有意保留以下限制：

- 向量索引只存在于 Python 进程内，重启即丢失；
- 每次 demo 都会重新加载模型、向量化文档和建立索引；
- 精确检索会遍历全部向量，不适合大规模知识库；
- 没有元数据过滤、混合检索和重排；
- 没有固定检索评测集和质量阈值；
- 生成层只校验引用编号存在，尚未验证每句话是否真的被引用证据支持；
- 尚未处理超时、重试、限流、并发、Token 预算和完整可观测性。

因此，“最小闭环已验证”不代表 RAG-004 至 RAG-006 的生产目标已经全部完成，这些长期需求继续保持“进行中”。
