# 学习 04：内存向量检索

## 我们现在处于哪里

```text
原始文本 -> 标准化 -> 文本块 -> Embedding -> 向量索引 -> Top-K 检索 -> 回答
                                                   ^
                                                当前步骤
```

本阶段先用 `InMemoryVectorIndex` 实现精确检索。它不是生产向量数据库，而是把向量数据库最核心的输入、输出和约束变成可观察、可测试的代码。

## 一条索引记录包含什么

`VectorRecord` 分为四部分：

- `id`：稳定的 chunk ID，用于更新和去重；
- `content`：文本块正文，用于后续生成回答；
- `vector`：Embedding 模型生成的定长向量；
- `metadata`：来源、位置等结构化信息，用于过滤和引用。

正文、向量和元数据彼此关联，但用途不同。检索计算只使用向量，返回结果时再携带正文和元数据。

## upsert 为什么不是简单 append

`upsert` 是 update 与 insert 的组合。同一个稳定 ID 第一次写入时新增记录，再次写入时替换旧记录。这样重复导入同一文本块不会产生多份重复数据，也为以后更新知识库奠定基础。

## 精确检索怎样工作

当前实现会遍历全部记录：

1. 计算 query 向量与每条记录向量的余弦相似度；
2. 按分数从高到低排序；
3. 返回前 `top_k` 条记录；
4. 分数相同时按记录 ID 排序，保证结果可复现。

如果有 N 条记录、每个向量有 D 个维度，一次搜索大约需要 `N × D` 次计算。它适合小规模学习和正确性基线，但数据量增大后会变慢。专用向量数据库通常使用近似最近邻索引，以少量召回损失换取更快的搜索。

## 为什么自动测试使用玩具向量

单元测试使用二维向量，可以准确控制 A、B、C 的预期顺序，验证的是“索引机制是否正确”。真实 Qwen 模型实验验证的是“语义表示是否有效”。

把两者分开后，如果结果异常，就能判断问题更可能来自模型还是索引逻辑。
