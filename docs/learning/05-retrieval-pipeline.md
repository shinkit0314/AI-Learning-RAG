# 学习 05：串联最小检索流水线

## 本阶段目标

此前已经分别验证了文本切分、Embedding 和内存向量索引。本阶段使用 `RetrievalPipeline` 把它们串成一条真实链路：

```text
文档 -> 标准化 -> chunk -> document embedding -> upsert
                                                    |
query -> query embedding -----------------------> Top-K 检索
```

这已经具备 RAG 中 Retrieval 的最小形态，但数据仍只保存在当前进程内，也尚未生成自然语言答案。

## 为什么维度不一致必须失败

索引创建时会固定向量维度。模型或配置改变后，如果输出维度与索引不同，流水线会立即报告错误，不会自动补零或截断。

Embedding 向量进入索引前，Transformer 的 attention 和 pooling 已经完成。索引比较的是最终向量的几何方向；随意修改维度会改变距离关系，并掩盖模型版本、降维配置或索引版本使用错误的问题。

Qwen3 Embedding 支持有计划的 Matryoshka 降维，但必须满足：

1. query 和所有 document 使用同一模型与同一目标维度；
2. 为该维度创建独立索引；
3. 重新生成全部已有文档向量；
4. 通过固定评测集比较降维前后的召回质量。

## 流水线保留了哪些信息

写入索引的每个 chunk 同时保留：

- 稳定 chunk ID；
- chunk 正文；
- 文档 ID、标题和来源；
- chunk 顺序及字符起止位置；
- 模型生成的向量。

因此搜索结果不仅有相似度，还能追溯到原始资料，为后续引用答案做准备。

## 自动测试与真实实验

自动测试使用二维假向量，稳定验证编排、Top-K、幂等写入和维度保护。`scripts/retrieval_demo.py` 则使用真实 Qwen 模型，验证本机 GPU 上的端到端语义排序。

真实实验运行命令：

```powershell
uv run --extra local-embedding python scripts/retrieval_demo.py
```

预期会索引三条记录并返回两条结果。具体分数由模型决定，不应把某个固定小数写成长期不变的正确答案。

## 首次真实实验结果

首次人工实验返回 B、A，而人工预期是 A、B。B 同时包含 RAG、检索、资料和生成回答，模型认为它与问题的整体语义更接近；A 对向量化作用的解释更直接，但没有明确出现 RAG。

这不是索引排序错误，而是“机械排序正确”与“语义排序是否理想”之间的区别。A、B 都进入 Top-2，说明有用证据已经被召回。该结果保留为基线，后续用 Query 改写、重排和检索评测集系统性优化，不针对单个样例硬调模型。
